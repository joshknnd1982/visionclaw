# VisionClaw and whole programs made accessible, window after window

## How to make a whole program accessible, every window of it
In the program, say: make every window of this program accessible. VisionClaw learns the window in front, plans the
fixes for all the windows it knows of the program, and asks once before it makes them in the program's add-on. Then move
to another window of it; VisionClaw learns that one too.

## How to learn a window and plan the fixes without making them yet
Say: learn this window, or: learn this window and make a plan to fix it. VisionClaw inspects the window, names controls
without a name from their pictures, and says its problems and its steps in the plan. Nothing is changed. To make them
later, say: make the planned fixes for this program.

## How VisionClaw knows that many windows belong to one program
Every window learned goes on the program's map, by its window class and its title without the document's name. However
many windows there are, they belong to the program, and a fix of its add-on works in all of them. Ask: which windows of
this program have you learned.

## What the accessibility plan of a program is, and how far it is
The plan holds every fix found in the program's windows, each once, the simplest first: names, being told of changes,
keys that press or read. Then what needs its window open, and what no add-on can fix. Ask: what's the plan for this
program, or: what's left to fix in this program.

## Learning other windows by itself when you move to them
After you ask once in a program, VisionClaw learns each new window of it when you move there and stay a moment. It reads
only NVDA's facts and asks no model. Choose in VisionClaw's settings to be told in one sentence, quietly, or only when
you ask. Say: stop learning windows of this program.

## A control named in one window keeps its name in the others
A name read from a control's picture is kept in the program's access notes. Where the same control is found in another
window, it gets that name again, without asking a model. A name from a picture is a guess, and is said to be one.

## What the program's map file holds, and forgetting it
The map is part of the program's access notes, a Markdown file in the folder access of VisionClaw's data: its windows,
and its plan with what is made. The file is yours. Say: forget the windows of this program. The fixes already made stay
in its add-on until you have it removed.

## What VisionClaw also uses: memories, scratchpads and NVDA's log
Steps about what you asked VisionClaw to remember about the program come first. A line on the program's scratchpad says
what VisionClaw knows of it, for the models working there later. After a window is learned, recent errors, freezes and
developer info from NVDA's log are said.
